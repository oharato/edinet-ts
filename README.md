# edinet-ts

EDINETのXBRLから財務数値を読み取り、**前年より利益率や収益性が伸びた企業を高速にスクリーニング・抽出**するための軽量TypeScriptライブラリ＆CLIです。

保存先・検索エンジンには **DuckDB** を採用しており、大量の決算書データを高速にSQL絞り込み・ソートできます。

---

## 主な機能

- **高精度な財務抽出**:
  - 対象は証券コードを持つ上場企業の有価証券報告書（120）と訂正有価証券報告書（130）。半期・四半期は対象外
  - 日本基準（J-GAAP）および国際財務報告基準（IFRS）に対応
  - 連結決算を優先抽出し、なければ単体決算を採用
  - 1つの有報から**当期と前期の数値を自動突合**
- **豊富な投資・財務指標の自動計算**:
  - **稼ぐ力**: 営業利益率、利益率前年比成長率、売上高・営業利益成長率
  - **キャッシュ創出力**: フリーキャッシュフロー（FCF = 営業CF + 投資CF）、営業CF
  - **資本効率・健全性**: ROE（自己資本利益率）、ROA（総資産利益率）、自己資本比率
  - **労働生産性・株主還元**: 従業員1人当たり営業利益、1株配当金（DPS）、配当成長率、EPS、BPS
- **DuckDB による高速スクリーニング**:
  - インメモリまたはファイルベースのDuckDBに一括ロード
  - 「利益率成長率 >= 20%」「ROE >= 15%」「フリーCFが黒字」などをSQLで瞬時に抽出
  - `--where "<SQL条件>"` で自由自在にフィルタリング可能
- **人間にもAIにもフレンドリーな自己案内**:
  - `edinet-ts schema` で利用可能な全カラム・型・単位・クエリレシピを表示
  - `edinet-ts schema --json` でAI向け構造化スキーマを出力

## クイックスタート (CLI)

### 1. 単一のXBRLファイルを解析する

```bash
node dist/cli.js parse --file ./test/test_data/CJ_2371_kakakucom.xbrl
```

**出力例**:

証券コード: 2371

### 2. 手元の原本アーカイブから一括インポートする

手元にある `archive.sqlite`（約3,700社分の有報原本）から DuckDB へ高速インポートできます。既定では有報（120）と訂正有報（130）を取り込み、訂正有報は同じ証券コード・決算期の行を上書きします。

```bash
# テスト用（100社）
node dist/cli.js import-archive --limit 100 --db ./data/screening.duckdb

# 全件インポート（約3,700社）
node dist/cli.js import-archive --db ./data/screening.duckdb
```

### 3. 条件を指定してスクリーニングする

```bash
# 例: 営業利益率 15%以上 かつ 自己資本比率 60%以上 かつ 利益率が前年比伸びている企業
node dist/cli.js screen --db ./data/screening.duckdb \
  --where "operating_margin_current >= 0.15 AND equity_ratio_current >= 0.60 AND operating_margin_growth_rate > 0"
```

**スクリーニング結果表示**:

`screen` は コード / 種別 / 提出日 / 会社名 / 決算期 / 売上 / 営業益 / 利益率 / 利益率成長率 / 自己資本比率 / ROE / FCF / 1人当たり営業益 を表形式で表示します。`--json` を付けるとJSONで出力します。

### 4. スクリーニング項目の確認 (`schema`)

```bash
# 人間向けの一覧表とクエリ例
node dist/cli.js schema

# AI / プログラム向けのJSONスキーマ
node dist/cli.js schema --json
```

### 5. EDINETから最新の有価証券報告書を差分同期する (`sync`)

手元のDuckDBを最新の状態に維持するために、EDINET API v2から最近開示された有報を取得し、差分更新します。**対象は証券コードを持つ上場企業の有価証券報告書（120）と訂正有価証券報告書（130）**です。半期・四半期報告書は対象外です。

```bash
# 直近7日分の有報を差分同期（デフォルト）
node dist/cli.js sync --db ./data/screening.duckdb

# 直近30日分の有報を同期
node dist/cli.js sync --days 30 --db ./data/screening.duckdb

# 期間を明示指定して同期（バックフィル）
node dist/cli.js sync --since 2026-03-01 --until 2026-03-31 --db ./data/screening.duckdb

# ダウンロードやDB更新を行わずに、対象書類の一覧と件数のみ確認 (Dry Run)
node dist/cli.js sync --days 14 --dry-run
```

- **訂正有報の反映**: 130 は同じ証券コード・決算期の行を上書きします。`doc_type_code` と `submitted_at` に訂正後の書類情報が残ります。
- **自動重複スキップ**: 同じ書類IDは再取得しません。訂正前の120が訂正後の130を上書きすることもありません。
- **バックフィル**: `--since` / `--until` で任意の期間を同期できます。
- **ローカルキャッシュ**: 取得したXBRLは `data/edinet-cache/` に一時保存し、取込後に削除します。残す場合は `--keep-cache` を指定してください。
- **環境変数**: `EDINET_API_KEY` を設定しておくと、`--api-key` オプションの入力を省略できます。
