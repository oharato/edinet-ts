# 用語集

更新日: 2026-10-23。edinet-tsの資料を読むための説明です。例の値は説明用です。財務用語は、このライブラリでデータを区別する際の意味を示します。

まず、1社の値を読む方法は[指標の選択](METRIC_SELECTION.md)、入力の書き間違いを減らす方法は[型付き入力定数](TYPED_OPTIONS.md)を参照してください。

## 財務データを読むための用語

| 用語・資料中の表記 | 短い意味 | 具体例 | 使う場面 |
|---|---|---|---|
| 連結・単体（`scope`） | 連結は企業グループ全体、単体は提出会社だけの範囲 | `Consolidated` / `NonConsolidated` | グループ全体と会社単独の売上を混ぜない |
| 会計基準（`accountingStandard`） | 財務諸表を作る際のルール | `J-GAAP`、`IFRS`、`US-GAAP` | 同じ名前の項目でも意味が違わないか確認する。定数があっても全基準の抽出対応を意味しない |
| 期末・時点（`instant`） | ある1日における残高などの対象日 | `2025-03-31`の総資産 | 貸借対照表などの残高を選ぶ |
| 期間（`startDate` / `endDate`） | 値を集計した開始日から終了日まで | `2024-04-01`〜`2025-03-31`の売上 | 終了日だけ同じ半期と通年を混ぜない |
| 通期・年初来累計・単四半期（`annual` / `ytd` / `quarterly`） | 集計期間の分類。年初来累計は対象年度の開始から途中まで、単四半期はその四半期だけ | 通期売上と半期累計売上 | 保存データの比較条件を揃える。自動分類ではない |
| 財務諸表 | 会社の資産・負債・収支などを示す書類 | 貸借対照表や損益計算書 | 数値が何を表すか確認する |
| 流動資産 | 財務諸表で流動資産として分類された資産の合計 | 現金・売掛金・棚卸資産などを含む区分 | このAPIでは会社が報告した`CurrentAssets`の値を読み、内訳から合計を作らない |
| 流動負債 | 財務諸表で流動負債として分類された負債の合計 | 買掛金や短期借入金などを含む区分 | このAPIでは会社が報告した`CurrentLiabilities`の値を読む |
| 負債合計 | 財務諸表に記載された負債全体の合計 | 流動負債と固定負債を含む報告値 | このAPIでは`Liabilities`の値を直接読み、他の項目を足して補わない |
| 流動比率（`currentRatio`） | 流動資産を流動負債で割った比率 | APIの`2`は200%。流動資産120・流動負債40なら`3` | 保存書類の同じ日付・範囲の会社を比べる。計算方法と除外理由は[流動比率](CURRENT_RATIO.md)を参照 |
| 近似値・厳密な分数 | 近似値は表示に使うnumber、分数は報告された十進値の商を保持したもの | `1/3`の表示は`0.3333333333333333`だが同じ値ではない | 流動比率の条件や並べ替えで、表示の丸めにより境界を取り違えない |
| 財務指標（metric） | 売上や資産など、取得・比較する項目 | 売上高のIDは`netSales` | 読みたい値や検索条件を指定する |
| BS・PL・CF | 貸借対照表・損益計算書・キャッシュフロー計算書の略 | BSの総資産、PLの売上高、CFの営業活動による資金の増減 | 残高と期間中の収支を区別する |
| 組替え・表示方法変更 | 比較しやすくするために、前の年度の項目の分け方や表示先を変えること | 合計は同じでも内訳の表示を変える | 前年の報告書と翌年の前年列を比べるとき、金額の差と表示の差を分ける |
| 訂正 | 公表した資料の内容を修正すること | 決算短信の顧客別売上表を直す | どの資料・期間・項目の訂正かを確認する。有報の訂正と短信の訂正を混同しない |
| 表示単位・丸め差 | 資料の表で使う金額の大きさと、端数処理で生じる差 | 百万円の表示値は円へ換算して比べる | 単位の違いを不一致と混同せず、丸め方が不明な差を勝手に一致扱いしない |
| 横断検索（screening） | 渡した複数企業のデータを条件で絞り、並べ替えること | 売上が指定値以上の企業を並べる | 保存済み集合を比較する。全市場のデータが自動で揃う意味ではない |
| 欠損（missing） | 指定条件で値を採用できなかった状態 | タグ不在、期間不一致、`nil` | 値のない項目を実際の0と区別する |
| 未対応（unsupported） | 基準や単位などを安全に扱えない状態 | 未対応の会計基準 | 取得できた文字列を無理に比較値へ変えない |
| 曖昧（ambiguous） | 候補を一つに決められない状態 | 同じ期間・範囲に複数の適合factがある | 書類内で先に出た値を黙って採用しない |
| 抽出根拠・来歴（`source` / `evidence`） | どの値を、どのタグ・対象期間・単位から選んだかの記録 | `source`は採用元、`evidence`は探索時点までの候補と理由 | 値を元データと突き合わせる。全候補の網羅監査や原本の真正性証明とは異なる |
| 正規化（normalization） | 元の項目名・表現を、決めた共通項目へ対応させること | 元タグを`netSales`という共通IDへ対応させる | 同じ意味の値を同じ名前で扱う。別の意味の科目を一緒にすることではない |

## プログラム・開発資料を読むための用語

| 用語・資料中の表記 | 短い意味 | 具体例 | 使う場面 |
|---|---|---|---|
| EDINET・XBRL | EDINETは開示書類の提出・閲覧の仕組み。XBRLは財務情報などに項目名を付けるデータ形式 | 保存済みの`.xbrl`ファイル | 書類をプログラムで読む |
| Node.js・npm・TypeScript | Node.jsはJavaScriptを動かす環境、npmは依存パッケージの管理ツール、TypeScriptは型で入力などを検査できる言語 | このリポジトリの指定バージョンで開発する | 利用・開発に必要な実行環境を揃える |
| SQLite | ファイルなどにデータを保存して検索できるデータベース | ダウンロード済み書類の一覧を保存 | 保存済み情報を繰り返し使う |
| XML | 名前付きの要素を入れ子にするデータの書式。XBRLの基礎 | `<要素名>値</要素名>` | XBRLの構造を確認する |
| タグ・taxonomy（タクソノミ） | タグは項目名、taxonomyは項目やその意味などを定めた体系 | `jppfs_cor:NetSales` | 元データの科目を識別する |
| fact | XBRLに記録された1件の値 | 売上のタグに記録された値 | 元の候補値を調べる |
| context・`contextRef` | contextは対象企業・期間・範囲などの定義。`contextRef`はそれを参照するID | `CurrentYearDuration` | どの時点・範囲のfactか確認する。ID名だけで条件を推測しない |
| entity | contextに記録された対象企業の識別情報 | `identifier`と`scheme`の組 | 別企業の値を混ぜない |
| dimensions | 全社・単体の区分や事業部門など、値の対象を細かく分ける情報 | セグメントのメンバー | 部門の値を全社合計として採用しない |
| namespace（名前空間） | 同じ項目名を別の定義と区別する情報。URIで定義元を識別する | `jppfs_cor`というprefixと対応するURI | 同名の会社独自タグを標準タグと混同しない |
| raw・decimal・`safeNumber` | この指標APIのrawは解析後の元の数値文字列、decimalは十進数表記。safeNumberは文字列へ戻しても値が変わらず、所定範囲内の場合のnumber | rawの`"123.4500"`とsafeNumberの`123.45` | 大きな整数や細かい小数の桁を落とさず保持する。原XMLのバイト列を保存する意味ではなく、numberでの計算の厳密性も保証しない |
| unit・`decimals`・`nil` | unitは単位、decimalsは精度を示す属性、nilは値がないことを示す指定 | JPY、`decimals="-6"`、`nil=true` | 単位・精度・欠損を区別する。decimalsを値の倍率と解釈しない |
| snapshot | ある書類・対象時点の値と識別情報をまとめたデータ | `FinancialSnapshot` | 明示したデータ集合を検索へ渡す |
| registry（辞書） | 指標IDと元タグ・単位・期間型などの対応を並べた定義 | `METRIC_REGISTRY.netSales` | 指標をどの条件で読むか確認する |
| API・CLI | APIはプログラムから呼ぶ入口、CLIは端末へコマンドを入力して使う入口 | `selectMetric()` / `edinet-ts screen` | 自分のコードへ組み込むか、端末で操作するかを選ぶ |
| 型・union型 | 入力や返値の形を表す約束。union型は許す候補を列挙した型 | `"asc"`または`"desc"` | TypeScriptで書き間違いを検出する。JSONの実行時検査は別に必要 |
| 定数・member | 定数は名前で参照できる決まった値。memberはその中の項目 | `SortOrder.Descending`のmemberは`Descending`、値は`"desc"` | エディターの候補から入力を選ぶ |
| `as const`・readonly・freeze | `as const`/readonlyは型上の変更制限、freezeは実行時の変更制限 | 入力定数の定義をfreezeする | 定義が書き換わることを防ぐ。データ内容の正しさを保証する仕組みではない |
| fallback | 第一候補が使えないときに別候補を探すこと | 上位タグから下位タグへの探索 | 許された代替範囲を確認する。厳密選択では連結から単体や前期へ切り替えない |
| JSON・wire値 | JSONはデータを文字列で保存・受け渡す書式。wire値はその受け渡しで実際に使う値 | `ComparisonOperator.GreaterThanOrEqual`のwire値は`"gte"` | コード上の定数名とJSON内の値を対応させる |
| branch・commit | branchは変更を進める作業系列、commitは変更を記録した時点 | 文書だけを変更するbranchとそのcommit ID | 作業を分離し、変更を特定する |
| PR・merge | PRは変更を見てもらう提案、mergeはその変更を対象branchへ取り込む操作 | Draft PRは確認途中の提案 | レビューと取り込みを区別する。PR作成だけでmainへ取り込み済み・配布済みにはならない |
| CI・テスト・build | CIは変更時などに検査を自動実行する仕組み。テストは期待する動作の確認、buildは配布に使うコードなどの生成 | テスト・型検査・buildの成功 | コードの検証状態を確認する。全市場の値の正しさを証明する意味ではない |
| fixture | 繰り返し検証に使う入力データ | 合成XBRL、保存済みXBRL | 同じ条件でテストを再現する |
