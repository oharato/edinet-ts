# edinet-ts 改善計画

全体の目標と、各段階を完了と判断する条件をまとめています。実装の有無だけでなく、原本照合・保存・運用までの残作業を確認するための計画です。

更新日: 2026-10-30（文書整理）。全段階の残工程を対象とし、無償・既存データを優先します。今回の整理で実装範囲や受入条件を縮小しません。

実装・原本照合・配布・運用の現在地は[実装追跡](IMPLEMENTATION_STATUS.md)で管理します。APIの使い方は[文書索引](../README.md)、過去の提案・PR順序・詳細な受入条件は[計画履歴](../history/ROADMAP_2026-10-28.md)を参照してください。

過去の「未着手」「確認待ち」を現状の判断に使わないでください。

## 目標と受入条件

単一銘柄の値を読む機能と、比較可能な複数社を検索する機能を対にして進めます。部分実装・限定検証を、その段階全体の完成とは扱いません。

| 段階 | 成果物・完了の判断 |
|---|---|
| 1 基盤 | 期間・scope・基準・通貨・来歴・訂正cutoffを明示。年次/累計/変則年度、連結/単体、外貨/特殊業種を区別し、不一致・欠損・0を混同しない。既存18指標の互換性を保つ |
| 2 財務明細 | BS/PL/CFの対応表・抽出・検索。基準や科目の意味差、重複加算・丸めを確認し、複数社/複数年度の原本・表示資料と照合する |
| 3 時系列 | 前年比・CAGR・平均残高指標。連続期間、前年0/負値、期首欠損、EPS/配当の株式基準を検査し、掲載値と独自計算を区別する |
| 4 企業マスター | 安定ID・コード/名称/業種/市場/状態の観測とas-of検索。コード再利用や法人同一性を推測で結合せず、法的イベント日と観測日を区別する |
| 5 人的資本 | 給与・人数・年齢・勤続・比率を対象組織/労働者区分/定義ごとに取得・比較。未開示/非該当/0と単位を区別する |
| 6a 事業・関係先 | セグメント・顧客・受注・関係会社の明細と逆引き。期間・行の役割・単位・出典を保ち、合計/個別や法人同定を混同しない |
| 6b 株主・統治 | 株主分類・政策保有・大量保有・役員・報酬・監査報酬。表の引用と一次原本、人数/株数/割合、基準日/観測日と履歴を分ける |
| 6c 設備 | 原表の簿価・面積・所在地と検索。所有/共有/賃借、物理的な物件と表の記載単位を区別する |
| 7 保存・更新 | 原本→抽出→保存→索引→公開。版/指紋を固定し、再開・重複投入・途中失敗・競合・訂正/取下げ・旧世代復帰を検証。既存データの保護と本番規模の性能/容量を確認する |
| 8 品質 | 母集団・年度・基準・指標ごとに、未取得/未開示/解析失敗/比較不能/利用可能を集計。独立した原本/PDF照合を行い、限定標本を全市場の保証にしない |
| 9 利用先 | 固定commit・配布物hash・来歴を保持して統合。値/検索/ESM/CJS/公開型と利用先回帰、旧vendorへの復帰を確認する |
| 10 外部補完 | 価格・分割・予想・IR/PDF・法人/不動産・AI。利用/保存条件、観測時点、費用、認証と検証範囲を明示し、未検証値を通常財務値へ昇格させない |

段階1と8は各機能の前提です。時系列計算には必要な財務明細、母集団検索には企業マスター、利用先統合には品質と固定配布物が必要です。外部補完の採否は[外部データの判断](EXTERNAL_DATA_DECISIONS.md)を参照してください。

## 進め方

1. 対象の原本・期間・基準と未対応境界を決め、既存APIを再利用できる最小の変更に分けます。
2. 入力検査・採用理由・欠損の区別を実装し、合成境界テストと必要な実原本の独立照合を行います。
3. 保存を伴う変更では、hash/版・原子性・再開・readOnly・旧世代を確認します。公開条件を満たす前に世代を切り替えません。
4. [実装追跡](IMPLEMENTATION_STATUS.md)へ、実装、確認した標本、配布物、運用反映と残工程を別々に記録します。

新しい依存・認証・費用、保存形式の大きな変更、取得や定期運用の変更は、その時点の利用者の指示と既存の承認範囲を確認して判断します。過去資料の確認待ちだけを理由に、既に認められた作業を止めません。
