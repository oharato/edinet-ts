# 企業マスター間の観測差分

`compareCompanyMasterSnapshots(previous, current)` は、完全なEDINETコードリスト二つを検査し、EDINETコード順の差分を返します。既存の `queryCompanyMaster` の入力検査を共有し、入力を固定してから比較します。

- `record-added`: 前のリストにない行。
- `record-absent`: 次のリストにない行。上場廃止や法人消滅とは断定しません。
- `attributes-changed`: 証券コード、法人番号、名称、提出者種別、上場区分、業種、決算日原文/月の変化。

各行はEDINET安定ID、変更属性、変更前後の行を持ち、結果は両snapshotの基準日・実観測時刻・出典URL/hashを保持します。`dateMeaning: "snapshot-boundaries"` は観測の両端です。改称・上廃・合併等の正確な発生日や法人同一性を認定する情報ではありません。証券コードの再利用によって別EDINETコードを結合しません。

同じ出典URL、基準日と実観測時刻の昇順が必要です。同一時点で異なるhash、同一hashで異なる行/基準日は拒否します。同じ基準日に後から観測した訂正リストは比較でき、同じ観測の再投入は空の差分です。行順や属性のキー順だけの差は変更にしません。出典hashは呼出元の宣言であり、このAPIは元CSVの真正性を認証しません。

市場区分、法的イベントの一次出典、別EDINETコード間の法人結合、履歴のDB保存と利用先反映は後続工程です。


実観測の確認: 2026-10-27基準の11,433行と、公式URLから再取得した2026-10-29基準の11,432行を比較し、追加3・消失4・属性変更2の計9件を確認。全行を別のPython処理で比較した差分と両端の出典が一致し、source/buildの出力も完全一致しました。上場区分の行数は3,813→3,812ですが、この差を特定日の上廃数と読み替えません。進行中の財務取得jobは元の3,813社を固定した計画として維持しています。


検証: 全134ファイル/3,651テスト・本体型検査・build・配布用NodeNext型使用例・CommonJSの実9差分が成功。既存のCSV/保存snapshot/knownAt検査が存在しない暦日（例: 2026-02-30）をDate.parseで補正していた不具合も修正し、分単位の有効な時刻の受入れは維持しました。この追加は固定配布物53eb2adより後のローカル実装です。

完全な観測の永続保存・再open検索・観測ID指定の差分は[企業マスター観測Store](COMPANY_MASTER_STORE.md)を利用できます。法的イベントの日付確定は引き続き対象外です。
