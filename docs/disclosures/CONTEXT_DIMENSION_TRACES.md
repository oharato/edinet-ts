# 表の行や対象を区別する指定を追跡する

XBRLの値がどの表の行や区分に属するか、その指定に使われた名前を追跡します。名前の宣言先が分かることと、会計上の意味が正しいことは分けて扱います。

実装時の記録: 実装・ローカル検証済み（main統合前）。財務値の選択規則や既存contextの返値は変更しません。

XBRLには、値が「どの会社・期間・表の行のものか」を表すcontextがあります。その中のdimension（次元）は、連結/単体や、表の何行目かなどを区別する指定です。新しい`traceContextDimensions()`は、その指定に使われた名前を解析後の情報から追跡する補助APIです。数値を合算したり、会社の同一性を判断したりしません。

## 何を確認できるか

たとえば`a:Row1Member`という名前は、`a`の宣言先が変わると別の意味になり得ます。このAPIは略号だけで判定せず、その場所で宣言された名前空間のURIと項目名を記録します。別の略号、既定の名前空間、contextや行指定の内部での再宣言も追跡します。

- `scenario`と`entity/segment`の指定を区別します。
- 名前で指定する`explicit`と、内容の構造を使う`typed`を区別します。
- 解決できた名前、使った宣言、その位置、扱えない理由を残します。
- 同じcontext IDの複数定義は上書きしません。同じ軸の重複も記録します。
- XBRL root直下のcontextだけを収集し、本文やtyped内容の中の同名要素を提出contextとして拾いません。

`resolved`は、解析後に保持された名前の宛先を解決できたという意味です。軸とメンバーがタクソノミ上で正しく組み合わされていることや、正しい表の行であることは証明しません。

返値の`dtsValidation: "not-performed"`で、参照する定義一式（DTS）の検証をしていないことを明示します。省略されたメンバーを定義から自動補完することもしません。

## APIの使い方

```ts
import { EdinetXbrlParser } from "edinet-ts";
const object = new EdinetXbrlParser().parse(xml, "SYNTHETIC");
const trace = object.traceContextDimensions("row-context");
console.log(trace.status, trace.candidates, trace.diagnostics);
```

書類番号・context IDは合成例です。状態は、証跡がない`missing`、名前を解決できた`resolved`、不解釈の内容がある`unsupported`、同じcontext IDの候補が複数ある`ambiguous`を区別します。`missing`は、そのcontextが原本に存在しないことの証明ではありません。

返値は内部情報のコピーです。返値を書き換えても、次回の照会や既存の財務抽出は変わりません。従来の`new EdinetXbrlObject()`も利用でき、証跡のない手組みObjectでは`missing`を返します。`clear()`で証跡も消えます。既存のObject/contextのJSON形に、新しい列挙可能なfieldを追加しません。

## 原本そのものの検証とは区別する

> 以下は各検証を実施した時点の記録です。件数・配布先・未確認範囲を含めて読み、現在の稼働状態とは分けてください。

既存parserは空白などを整えるため、新しいtraceでも元XMLの字面すべては復元できません。`raw`や`parsedUri`はparserが保持した表現です。

返値の`originalLexicalValidation: "not-performed"`は、元XMLのQNameの字面を検証していないことを示します。たとえば解析前に失われた特殊な空白を、あとから検出できたとは扱いません。

保持された不正QName、未宣言の略号、解釈できない名前空間、数値参照のように元の表現を区別できない場合は、推測で直さず診断します。typedの`parsedContent`も解析済みの内容で、元XMLの順序・空白・字面を完全に再現するものではありません。typed内容を、名前で指定したメンバーへ置き換えません。

既存の金融selectorが未知の次元を拒否する規則は維持します。このtraceだけを根拠に、その拒否を解除しないでください。連結子会社の人的資本表に記載された会社ラベルなどの行抽出は、対象タグ・軸・期間・単位・出典を別に確認する後続機能です。一般的な子会社一覧や法人の名寄せは今回の機能ではありません。

手でObjectのデータやcontextを追加しても、原本に由来する証跡を自動で再計算しません。同じcontext IDの追加は曖昧として扱います。別の原本は改めてparseしてください。`declaredAt`は解析木の場所を説明する情報で、元XMLの行番号や完全な字面の位置を表すものではありません。
